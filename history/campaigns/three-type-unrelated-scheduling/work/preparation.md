# Testing foundation

The [contract](contract.md) fixes both decision predicates. Z3 5.1.0 models
integer allocation counts, exact column sums and machine capacities. A model
is a legal schedule because independent jobs can run consecutively on each
machine; every legal schedule gives such counts. Returned counts are checked
with Python integer arithmetic. Only UNSAT means NO; other statuses raise.
The source oracle enumerates equal-cardinality subsets on finite test inputs.

[Self-test evidence](evidence/preparation/self-test.json): eight source cases,
192 two-machine/three-type checks against exhaustive allocation enumeration
(81 NO), one zero-job boundary check, invalid witness checks, and three rejected
subprocess fixtures: malformed output, wrong decision and wrong recovery.
The enumeration covers processing times in {1,2}, one job per type, and
thresholds 1,2,3. These checks validate a finite domain, not Z3 generally.

Run `python3 campaigns/three-type-unrelated-scheduling/work/check.py --self-test`.
`--candidate PATH` injects the eight cases and tests recovery on up to three
solver-generated target witnesses each. No actual reduction or recovery has
been tested. Test-only fault programs were temporary and are regenerated by
the self-test. No timeouts or new dependencies were introduced.

The source card remains on proof-route hold. The user approved a bounded
exploration of this candidate; that authorization does not establish admission
as a moderate-difficulty problem. All writes during this campaign stay here.
